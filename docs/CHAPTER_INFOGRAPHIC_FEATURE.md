# Chapter Infographic ("Chapter at a Glance") — Feature Context

> **Status (2026-08-17):** live on 26 chapters — Grade 12 Biology Ch 9, all 10
> Grade 5 EVS chapters (replaced once with a stronger batch), and all 15 Grade
> 5 Maths chapters (12 replaced; 13-15 rejected on review, still on their
> original poster — see open items). Grade 5 is complete. 266 of 292 in-scope
> chapters remain.
>
> **Read this first** if you are picking up the infographic rollout in a new
> session. It explains what exists, where it lives, how to add a chapter, and
> the traps that already cost a debugging round.

---

## 1. What the feature is

At the end of a chapter's final lesson step, the student sees a one-page
revision poster — the "Chapter at a Glance" wall-chart. It is an **authored
image**, generated by GPT-5.5 during a manual handover step, hosted in Supabase
Storage, and referenced from the lesson markdown by a fenced block.

The student-facing behaviour:

- A framed preview appears at the bottom of the final lesson step, under a
  `## Chapter at a glance` heading.
- Poster text is unreadable at column width, so the preview carries a
  **"Tap to enlarge"** affordance. Clicking opens a full-screen viewer where
  the image renders at natural size and the student pans around it.
- A **"Chapter at a glance"** navigation entry appears directly below the last
  milestone and above "Wrap-up" — in the "On this chapter" outline for Grades
  9-12 (`StudyRenderer`) and the "Chapter path" rail for Grades 5-8
  (`JourneyRenderer`). It appears only for chapters that actually have a poster.

## 3. How a chapter gets a poster

One command does everything — optimise, upload, record, apply, and invalidate
the cache:

```bash
cd backend
python3 scripts/apply_chapter_infographic.py \
    --image ~/Downloads/poster.png \
    --grade "Grade 12" --subject Biology \
    --chapter "Chapter 9: Biotechnology: Principles and Processes" \
    --alt "One-page revision poster covering ..." \
    --caption "Full-chapter revision poster — ..." \
    --dry-run     # always dry-run first
```

The steps it performs:

1. **Optimise** — converts to WebP, downscales to `MAX_EDGE = 2000`. A ~2 MB
   GPT-5.5 PNG lands at roughly 240 KB with no visible loss. This matters:
   students are on mobile data.
2. **Upload** — to the existing **public** `rag-visuals` Supabase bucket, at
   `chapter-infographics/<board>/<grade>/<subject>/<chapter-slug>.webp`.
3. **Record** — writes a sidecar JSON under
   `backend/app/data/chapter_infographics/<grade>/<subject>/<chapter>.json` so
   the applied state is tracked in git.
4. **Apply** — appends a ` ```chapter-infographic ` fence under a
   `## Chapter at a glance` heading on the target step (default:
   `Revision and recap`).
5. **Refresh the chapter doc** — see §5, trap 1. This is not optional.

Re-running is **idempotent**: it replaces the existing block rather than
appending a second copy. It also strips a `chapter-summary` block if present,
so a chapter never shows both the text wall-chart and the poster.

Other modes:

```bash
# Re-apply everything already recorded (image already hosted)
python3 scripts/apply_chapter_infographic.py --dir app/data/chapter_infographics

# Remove a previously applied poster
python3 scripts/apply_chapter_infographic.py --remove \
    --grade "Grade 12" --subject Biology --chapter "Chapter 9: ..."
```

### The fence

````markdown
## Chapter at a glance

```chapter-infographic
{
  "url": "https://<project>.supabase.co/storage/v1/object/public/rag-visuals/...webp",
  "alt": "Screen-reader description — REQUIRED",
  "caption": "Optional line shown under the poster",
  "width": 1183,
  "height": 1329
}
```
````

`alt` is **required**, not optional. The poster replaces a chapter's text recap,
so without it a screen-reader user gets nothing at all. `width`/`height` are
optional but strongly preferred — they let the renderer reserve the aspect ratio
so a 240 KB image does not shove the lesson down the page as it loads.

Validation fails safe: a malformed or unsafe payload renders **nothing** rather
than a broken image frame. `javascript:` and `data:` URIs are rejected, since
the `<img src>` is built from database content.

## 5. Traps — each of these already caused a bug

### Trap 1: the chapter doc is a second cache, and it shadows `lesson_cache`

**Grades 9-12 do not read `lesson_cache` directly.** They are served the Chapter
Journey view, which reads a stored `lesson_chapter_doc` row converted from
`lesson_cache`. Writing to `lesson_cache` alone means the student keeps seeing
whatever the doc was last built from — which looks exactly like "the change
didn't work".

`apply_chapter_infographic.py` and `apply_chapter_summary.py` now both call
`refresh_chapter_doc()` after a successful write. **Any new script that edits
`lesson_cache` must do the same.** The failure is silent and looks like a
frontend bug, which is what makes it expensive.

From the UI there is a **"Refresh lesson"** button that hits
`GET /api/lesson/chapter-doc?refresh=true` and rebuilds the same way — that is
the no-terminal fix.

### Trap 1b: Grade 4/5 — the step you target is NOT the milestone title

`chapter_doc_service._LEGACY_STEP_TITLES` remaps Grade 4/5 milestone titles to
the `lesson_cache` rows that actually feed them, and tries the **mapped** title
FIRST, falling back to the literal title only if the mapped row is missing:

| Grade 5 milestone title | `lesson_cache.step_title` actually used |
|-------------------------|------------------------------------------|
| What We Learn           | `Concept introduction` |
| Worked Examples         | `Worked examples` |
| Recap                   | **`Revision and recap`** |

Grade 5 EVS chapters have rows under BOTH `Recap` and `Revision and recap`.
Targeting `--step "Recap"` writes to a row the converter ignores: the apply
reports success, the chapter doc rebuilds, and the poster still never appears.
Use the script's default `--step "Revision and recap"` for Grade 4/5 as well.

Symptom to check for: the fence is present in `lesson_cache` but
`0/N` chapter docs carry it. Verify against the DOC, never the cache row.

### Trap 2: mobile has no per-fence renderer hook

React Native's markdown renderer has no equivalent of react-markdown's `code`
component override. A fence left in the text renders as **a wall of raw JSON**
on the student's phone.

Mobile therefore calls `extractChapterInfographics()` *before* handing text to
the renderer, inside `MathAwareMarkdown` — which covers both the Lessons tab and
`ChapterJourney` in one place. Any new fence type needs the same treatment or it
leaks on mobile.

Note: `visual-json` and `extract-ref` fences are **still exposed** on the mobile
Lessons tab (pre-existing, unrelated to this feature). Worth fixing separately.

### Trap 3: `<pre>` wrappers break block components

ReactMarkdown wraps every fenced block in `<pre>`, which forces monospace and
`white-space: pre` onto whatever it contains — visually breaking a card or
poster. Both `LessonSections.jsx` and `journey/LessonMarkdown.jsx` unwrap it,
detecting the language from the **hast AST node**, not the rendered children (by
then the `<code>` has already become a component with no `className`).

### Trap 4: the outline anchor only renders on `concept` blocks

`findChapterGlance()` in `StudyRenderer.jsx` matches **only** `type: "concept"`
blocks, because that is the only branch of `StudyBlock` that renders `anchorId`.
Matching any block type would put a dead link in the outline. The chapter-doc
converter currently emits the `## Chapter at a glance` section as a `concept`
block — if that ever changes, the link silently stops scrolling.

### Trap 5: the frontend dev server needs a hard reload

New component files plus changed import graphs mean the running Vite bundle is
stale. Hard-reload the browser (`Cmd+Shift+R`) after pulling these changes.

## 6. Design decision: image vs. structured text

Both exist in the codebase. **The image (`chapter-infographic`) is the chosen
direction**; the text version (`chapter-summary`) was built first, rejected, and
retained.

The text renderer — `ChapterSummaryBlock.jsx`, `shared/utils/chapterSummary.js`,
`apply_chapter_summary.py`, `backend/app/data/chapter_summaries/` — is fully
working and tested but **no longer applied to any chapter**. The Grade 12
Biology sidecar under `chapter_summaries/` is stale relative to the DB. Delete
that whole path if the image approach is confirmed permanent.

Known trade-offs accepted by choosing the image:

- Poster text is **not** searchable, RAG-indexable, translatable to Hindi, or
  screen-readable beyond the `alt` string.
- Correcting a typo means regenerating and re-uploading the image, not editing
  a JSON field.
- **GPT-5.5 image generation makes content errors on dense technical text.** In
  the first batch of three Biotechnology posters: one contained an off-topic
  "C3 vs C4 Plants" panel and a meta "Why Exemplar Questions are Harder?" panel;
  two had garbled DNA sequence text (`ЄAATTC`, `ЯAATTC`) in the sticky-ends
  diagram. The poster that shipped was chosen by manual review.

**This is the main open risk for the 292-chapter rollout: at that volume nobody
will eyeball every poster, and generated posters demonstrably contain factual
and rendering errors.** A review gate is needed before bulk-applying. See §7.

## 6a. The authoring batch (generated 2026-08-17)

All 292 prompts for the first cut are already generated:

```
~/Downloads/GPT55_Chapter_Infographic_Prompts_2026-08-17/
  00_README_and_index.txt          <- start here; has the review gate
  grade_5/maths/01_..._PROMPT.txt
  grade_5/evs/...
  ...
  grade_12/biology/...
```

Regenerate at any time (idempotent, writes a folder stamped with that day's
date):

```bash
cd backend
python3 scripts/prepare_gpt55_infographic_prompts.py --dry-run   # counts only
python3 scripts/prepare_gpt55_infographic_prompts.py
python3 scripts/prepare_gpt55_infographic_prompts.py --grade "Grade 8" --subject Science
```

Each prompt is grounded in that chapter's authored `lesson_cache` text and
adapts by grade band (density, vocabulary, closing strips) via
`app/services/infographic_prompt.py`. It also instructs the model to return
`ALT:` and `CAPTION:` lines as text after the image — feed those straight into
`--alt` and `--caption`.

The prompt's HARD RULES section encodes the three observed failure modes
(off-topic panel, meta panel, garbled lettering). Treat it as a defect log: if
a new failure mode shows up during the rollout, add a rule there rather than
fixing posters one at a time.
